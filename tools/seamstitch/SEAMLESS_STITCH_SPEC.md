# SEAMLESS_STITCH_SPEC.md — Seam-Invisible Stitcher for Chained AI Video Segments

> **How to use this file:** drop it into your repo root, then prompt your coding agent:
> *"Implement the tool described in `SEAMLESS_STITCH_SPEC.md`. Build the test fixtures and run the test plan in §10, iterating until every item in the acceptance checklist (§11) passes."*

---

## 1. Goal

Build a cross-platform CLI tool (`seamstitch`) that concatenates N video segments generated by chained image-conditioned video generation (Seedance 2.0 workflow: last frame of segment *i* is used as the first-frame condition of segment *i+1*) into a single video where the joints are visually and audibly invisible.

The tool must fix the specific artifact of this workflow: **each generated segment drifts slightly in exposure / white balance relative to the previous one**, so a naive concat shows a small lighting "pop" at every joint, plus a 1-frame motion hitch from the duplicated boundary frame.

## 2. Background / problem statement

- Segments are H.264/AAC MP4s (typically 24 or 30 fps, 1080p or 720p), each ~5–15 s.
- Segment *i+1*'s first frame has (nearly) the same **content** as segment *i*'s last frame, but the generator does not perfectly preserve **grade** (brightness, contrast, colour temperature). The shift is global and roughly uniform across the segment.
- Audio is generated per segment and is currently crossfaded successfully; that behaviour must be preserved.
- Current manual pipeline: per-pair ffmpeg commands + hand-tuned fixes. We want one deterministic, automated command.

## 3. Core approach (agreed design — do not redesign)

1. **Colour-match each segment to its predecessor** by comparing the two boundary frames (near-identical content ⇒ statistical matching is well-posed), baking the correction into a **Hald CLUT PNG**, and applying it with ffmpeg's `haldclut` filter.
2. **Ramp the correction out** over the first `--ramp` seconds of each segment (default 2.0 s), so every segment returns to its native grade — the grade its *successor* was conditioned on. This makes each pairwise correction independent (no cascade drift). `--ramp 0` selects full-clip correction with numeric cascading instead (§7.4).
3. **Drop the duplicated boundary frame** (first frame of segments 2..N) *and trim the matching audio duration* to prevent cumulative A/V drift.
4. **Short video crossfade (`xfade`) mirrored by `acrossfade`** at each joint (default 0.25 s) as insurance.
5. Optional global `deflicker` pass.
6. **Single `filter_complex` graph, single encode** — no intermediate re-encodes, no temp video files.


A single-file `stitch.py` is acceptable if it stays under ~600 lines; the module layout above is preferred. Keep `graph.py` logic pure (inputs: probed metadata + options; output: filter graph string + arg list) so it is unit-testable without ffmpeg.

## 5. Environment & dependencies

- Python ≥ 3.10, `numpy`, `imageio` (Pillow backend). No OpenCV, no scipy (matrix sqrt via `np.linalg.eigh`).
- ffmpeg/ffprobe ≥ 5.0 on PATH (`xfade`, `acrossfade`, `haldclut`, `haldclutsrc`, `deflicker` all required). Check at startup; exit with a clear install hint if missing or too old.
- Must run on macOS (Apple Silicon), Linux, Windows. All subprocess calls use **argument lists** (`subprocess.run([...])`), `pathlib` paths, no `shell=True`, no `bc`/shell arithmetic — all math in Python.

## 6. CLI specification

```
python -m seamstitch SEG1 SEG2 [SEG3 ...] -o OUTPUT.mp4 [options]

Positional:
  SEGS                 2+ input segments, in order. Also accept a single glob
                       (natural-sorted); print the resolved order and proceed.

Options:
  -o, --output PATH    required
  --xfade FLOAT        video+audio crossfade seconds per joint (default 0.25).
                       0 = hard cut via concat filter (both streams).
  --ramp FLOAT         seconds to ease colour correction back to native grade
                       (default 2.0). 0 = full-clip correction with cascading.
  --method {hybrid,mkl,quantile,none}   default hybrid. `none` skips colour
                       matching (baseline / A-B testing).
  --deflicker          append deflicker=size=25 to the final video chain.
  --crf INT            default 17        --preset STR   default slow
  --audio-bitrate STR  default 192k
  --fps FLOAT          override target fps (default: fps of first segment)
  --temp-dir PATH      default: tempfile.mkdtemp(); --keep-temp to retain
  --verify             run §9 metric on the output and print a per-joint report;
                       exit non-zero on FAIL
  --dry-run            print probe summary, LUT plan, full ffmpeg arg list and
                       filter graph; render nothing
  -v, --verbose        log all executed commands
```

**Constraint:** a single `--xfade` value drives both `xfade` and `acrossfade`. Unequal fade lengths would desynchronise A/V because both fades shorten their stream by the fade duration per joint.

## 7. Pipeline phases (implementation detail)

### 7.1 Phase 1 — Probe & normalise plan

For each segment, via `ffprobe -of json`:

- video: `r_frame_rate`, `width`, `height`, `pix_fmt`, `color_range`, `color_space`, `color_primaries`, `color_transfer`, frame count (prefer `-count_packets` → `nb_read_packets`; fall back to `nb_frames`, then `format.duration × fps`).
- audio: presence, `sample_rate`, `channel_layout`.

Rules:

- Target fps/resolution = first segment's (or `--fps`). Any mismatching segment gets `scale=W:H:flags=lanczos` + `fps=` in its branch; warn.
- Segment with no audio stream → substitute `anullsrc` (matching rate/layout, exact segment duration) so the audio graph stays uniform; warn.
- Fail with a clear message if any segment's video duration < `2·xfade + 1 frame`.
- Clamp `ramp` per segment to `L_j − xfade` (see §7.5 for L_j); warn if clamped.
- Duration math: `fd = 1/fps`; durations derived from frame counts (`nframes × fd`), not container duration, wherever possible.

### 7.2 Phase 2 — Boundary frame extraction

For each joint *i → i+1*:

```
ffmpeg -y -sseof -0.2 -i seg_i.mp4  -frames:v 1 -update 1 {tmp}/last_i.png    # last frame
ffmpeg -y -i seg_{i+1}.mp4 -frames:v 1 {tmp}/first_{i+1}.png                  # first frame
```

Load with imageio, strip alpha (`[..., :3]`), keep uint8.

**Sanity check:** compute mean absolute luma difference between `last_i` and `first_{i+1}` (Rec.709 luma). If > 35 (8-bit scale), warn loudly: *"Boundary frames for joint i→i+1 do not appear to correspond — check segment order"* (do not abort).

### 7.3 Phase 3 — Colour transform + Hald CLUT baking (numpy)

For statistics, downsample both boundary frames to ≤ 512 px on the long edge (stride slicing is fine); the resulting LUT is resolution-independent.

`src` = first frame of segment *i+1* (the segment being corrected). `ref` = reference frame from segment *i* (§7.4).

**Quantile (per-channel, handles nonlinear tone shifts):**

```python
def quantile_lut_8bit(src_ch, ref_ch, n_q=1024):
    qs = np.linspace(0.0, 1.0, n_q)
    s = np.quantile(src_ch, qs).astype(np.float64)
    r = np.quantile(ref_ch, qs).astype(np.float64)
    s += np.linspace(0.0, 1e-4, n_q)              # strictly increasing xp for interp
    lut = np.interp(np.arange(256), s, r)
    lut = np.maximum.accumulate(lut)               # enforce monotonic
    return np.clip(np.round(lut), 0, 255).astype(np.uint8)
```

**MKL (Monge–Kantorovich linear, handles cross-channel colour casts):**

```python
def mkl_transform(src_px, ref_px, eps=1e-6):
    # src_px, ref_px: (N,3) float64 in [0,1]
    mu_s, mu_r = src_px.mean(0), ref_px.mean(0)
    cov_s = np.cov(src_px, rowvar=False) + eps * np.eye(3)
    cov_r = np.cov(ref_px, rowvar=False) + eps * np.eye(3)
    def psd_sqrt(m):
        w, v = np.linalg.eigh(m)
        return (v * np.sqrt(np.clip(w, eps, None))) @ v.T
    cs = psd_sqrt(cov_s); cs_inv = np.linalg.inv(cs)
    T = cs_inv @ psd_sqrt(cs @ cov_r @ cs) @ cs_inv   # symmetric
    return T, mu_s, mu_r
# apply to (N,3) pixels x in [0,1]:  y = np.clip((x - mu_s) @ T + mu_r, 0, 1)
```

**Hybrid (default): MKL first, then per-channel quantile refinement.**
Compute `src_mkl = clip((src − μs)·T + μr)`, then `lut_c = quantile_lut_8bit(src_mkl[:,c]·255, ref[:,c]·255)` per channel. The full mapping is `f(x) = lut[ mkl(x) ]`.

**Bake into a Hald CLUT PNG:**

```
ffmpeg -y -f lavfi -i haldclutsrc=8 -frames:v 1 {tmp}/hald_identity.png   # 512×512, 64 levels/ch
```

Apply `f` (whichever method) to the identity image's pixels, write `{tmp}/lut_{i+1}.png` as **8-bit RGB (no alpha)**. Expose the mapping as a plain Python callable `f_i(frame_uint8) -> frame_uint8` as well — needed for cascading. Level 8 + ffmpeg's default interpolation is sufficient; if banding is ever observed, `haldclutsrc=16` (4096×4096) makes the 8-bit mapping exact — leave as a constant, not a CLI flag.

### 7.4 Reference-frame selection (ramp vs cascade)

- **Ramp mode (`ramp > 0`, default):** by the end of segment *i* its grade has returned to native, so `ref` for joint *i→i+1* is simply the **native** `last_i`. Corrections are pairwise-independent.
- **Cascade mode (`ramp == 0`):** segment *i* is uniformly corrected by `f_i`, so `ref = f_i(last_i)` computed **in numpy** (`f_1` = identity). Never re-render or re-extract to get the corrected reference.

### 7.5 Phase 4 — Graph assembly & offset math

Definitions (`fd = 1/fps`, `xf = xfade`):

```
L_1 = nframes_1 · fd
L_j = (nframes_j − 1) · fd          for j ≥ 2   (duplicate boundary frame dropped)
OFF_k = Σ_{j=1..k} L_j − k·xf                    (offset of the xfade joining segment k+1)
expected_duration = Σ L_j − (N−1)·xf
```

**Round every OFF_k to the frame grid:** `OFF_k = round(OFF_k · fps) / fps`, formatted with ≥ 6 decimals. Frame-count-derived durations keep this exact.

Per-segment video branch:

- Segment 1: `[0:v] settb=AVTB, fps={fps}, format=yuv420p [v0]` (plus `scale` if normalising).
- Segment j ≥ 2 (with `lut_j.png` as an extra input):

```
[j:v] trim=start_frame=1, setpts=PTS-STARTPTS, settb=AVTB, fps={fps}, format=yuv420p, split=2 [o][r];
[o][{lutidx}:v] haldclut [c];
[c][r] xfade=transition=fade:duration={ramp}:offset=0 [vj]        # ramp: corrected -> native
```

With `ramp == 0`, skip the split/ramp-xfade and use the `haldclut` output directly. With `method == none`, skip `haldclut` entirely (keep the trim).

Joint chain: `[v0][v1] xfade=transition=fade:duration={xf}:offset={OFF_1} [j1];` then `[j1][v2] xfade=...offset={OFF_2} [j2];` … If `--deflicker`, append `deflicker=size=25` after the last joint. Label the end `[vout]`.

Audio (j ≥ 2 trims **exactly one video frame's duration** to stay in sync):

```
[j:a] atrim=start={fd:.9f}, asetpts=PTS-STARTPTS [aj]
[a0][a1] acrossfade=d={xf} [ja1];  [ja1][a2] acrossfade=d={xf} [ja2]; ...
```

`--xfade 0`: replace both chains with `concat=n=N:v=1:a=1` (same trims/ramps still apply); README notes hard audio cuts may click.

Final command shape:

```
ffmpeg -y -i seg1 .. -i segN -i lut_2.png .. -i lut_N.png \
  -filter_complex "<graph>" -map "[vout]" -map "[aout]" \
  -c:v libx264 -crf {crf} -preset {preset} -pix_fmt yuv420p \
  -c:a aac -b:a {audio_bitrate} -movflags +faststart -shortest {output}
```

Propagate source colour metadata when present (`-colorspace`, `-color_primaries`, `-color_trc`, `-color_range` from the probe of segment 1).

**Worked example** — 3 segments, 24 fps, exactly 120 frames each, `xf=0.25`, `ramp=2.0`:
`fd=0.0416667`, `L1=5.0`, `L2=L3=4.9583333`, `OFF_1=4.75`, `OFF_2=9.4583333` (=227 frames exactly), expected duration `14.4166667`.

### 7.6 Phase 5 — Render & report

Stream ffmpeg stderr through; on success print expected vs probed output duration (must match within 1 frame + AAC padding tolerance) and, if `--verify`, the §9 report.

## 8. Determinism & hygiene

- Identical inputs + options ⇒ identical graph string (unit-tested).
- All temp artifacts under one temp dir; removed unless `--keep-temp`.
- Type hints throughout; no globals; `verify` and `graph` importable as library functions.

## 9. Verification metric (`verify.py`, also `--verify`)

1. Compute joint fade windows `[OFF_k − 0.1, OFF_k + xf + 0.1]` from §7.5 math.
2. Decode luma around each joint (±0.6 s) straight to numpy:
   `ffmpeg -ss .. -t .. -i out.mp4 -vf format=gray -f rawvideo -` (known W×H ⇒ reshape).
3. Per joint: `step = max(mean |Y_t − Y_{t−1}|)` over consecutive frame pairs inside the fade window; `baseline = median(mean |Y_t − Y_{t−1}|)` over the surrounding window excluding the fade.
4. Window check: `|mean(Y over 0.5 s before joint) − mean(Y over 0.5 s after)| = drift`.
5. **PASS** iff `step ≤ max(2.0, 1.5·baseline)` **and** `drift ≤ 1.5` (8-bit scale). Print a per-joint table (step, baseline, drift, verdict); exit non-zero if any joint fails.

## 12. Known gotchas (read before coding)

1. `xfade` requires identical resolution, pix_fmt, fps **and timebase** on both inputs — hence `settb=AVTB, fps=, format=yuv420p` on every branch. If a timebase error still appears after `haldclut`/ramp-`xfade`, add another `settb=AVTB` before the joint chain.
2. Dropping the duplicate **video** frame without trimming `fd` of **audio** accumulates ~42 ms desync per joint at 24 fps — the atrim in §7.5 is mandatory.
3. `haldclut` uses framesync: the single-frame PNG input's last frame is repeated for the whole stream. If a build misbehaves, loop the PNG input (`-loop 1`) and rely on the finite main input to end the stream.
4. Last-frame extraction: `-sseof -0.2 … -frames:v 1 -update 1` writes the final decoded frame over itself; plain `-sseof -0.01` can decode zero frames.
5. Round xfade offsets to the frame grid (§7.5) — float drift accumulates across many joints and can double a frame at a joint.
6. imageio can return RGBA or 16-bit for PNGs — normalise to uint8 RGB on load; write LUT PNGs as uint8 RGB.
7. AAC priming/padding makes audio a few ms longer than video — `-shortest` on the final mux; tolerate ±50 ms in duration assertions.
8. `deflicker` is temporal smoothing: it can soften fast intentional exposure changes, which is why it's opt-in.
9. Preserve `color_range`/colourspace flags from the source; `haldclut` operates in RGB and ffmpeg auto-inserts conversions — missing flags on full-range sources cause washed output.
10. Quantile `np.interp` needs strictly increasing xp — the epsilon ramp in §7.3 handles flat quantile runs (e.g., letterboxed black).
11. Statistics on downscaled boundary frames; LUT application is full-res by construction.
12. Never build filter graphs via string concatenation with user paths inside — paths only ever appear in the argv list.

## 13. Out of scope (do not build)

Linear-light / colour-managed matching, local or masked matching, motion interpolation at joints, GUI, scene detection, per-segment sidecar metadata, GPU encoders (may be a later `--codec` flag). Keep the surface small; correctness of the seam is the whole point.
